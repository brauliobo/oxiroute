# Local-v2 reverse HTTP/1.1 baseline - 2026-07-23

## Result

The repository load generator sent explicit HTTP/1.1 requests and verified persistent connection
reuse, response framing, status, and body size. Three measured 30-second repetitions completed per
implementation with zero failed or non-2xx/3xx requests.

| Implementation | R1 req/s | R2 req/s | R3 req/s | Median req/s | Population CV |
| --- | ---: | ---: | ---: | ---: | ---: |
| Direct nginx origin | 483,813 | 391,837 | 375,900 | 391,837 | 11.40% |
| nginx 1.30.4 | 204,152 | 144,387 | 132,559 | 144,387 | 19.54% |
| HAProxy 3.4.2 | 167,061 | 148,048 | 147,660 | 148,048 | 5.87% |

OxiRoute's low dispersion establishes a usable product baseline of 92,605 requests per second for
interleaved before/after optimization checks on this host. The direct origin and nginx results
declined materially during the series. Their coefficients of variation are too high for strong
cross-product conclusions, so the median ratios are retained only as descriptive data in the JSON
report.

## Method

- Scenario: plaintext HTTP/1.1 reverse proxy over loopback with a fixed 1,024-byte response.
- Load: `oxiroute-loadgen 0.1.0`, 128 persistent connections, one in-flight request per connection,
  10-second warm-up, and 30-second measurement.
- Request: `GET /payload HTTP/1.1` with explicit `Host` and `Connection: keep-alive` fields.
- Repetitions: three per implementation in an interleaved order.
- Ports: nginx origin `127.0.0.1:39080`, sequential proxy `127.0.0.1:39081`.
- CPU affinity: proxy CPU 2, nginx origin CPU 3, load generator CPU 4.
- Concurrency: one OxiRoute/Pingora service thread, one nginx worker, one HAProxy thread.
- Product source: `983e872cb56181f5195121cb417bc8fa9ba0e34c`.
- OxiRoute binary SHA-256:
  `5f8b7f378ec9ccd71d4cb987a5f4261315a5957e5ea5c1be181211ff10d2604b`.
- Load-generator binary SHA-256:
  `f1ee441510eec34260a165ebf501811f0e3b04b500e9f2cdfcd2d05dc1312cfc`.
- Host: AMD Ryzen 7 9700X, Linux `7.1.3-2-cachyos`, 16 logical CPUs.

The configured default origin port was occupied by an unrelated process before this series, so the
preflight-approved alternate ports above were used. Ports do not affect the request or proxy
configuration semantics.

## Limitations

- The host used the `powersave` governor with boost and SMT enabled. CPUs were pinned but not
  isolated from kernel or workstation activity.
- Origin and nginx drift makes this report unsuitable for precise cross-product ranking.
- The load generator is closed-loop and subject to coordinated omission. This report contains
  throughput and failure counts, not tail-latency distributions.
- Access logging was disabled and all products used one worker/thread, matching OxiRoute's current
  fixed service-thread behavior.
- No TLS, HTTP/2, HTTP/3, remote-network, multi-core, memory, CPU-counter, or long-duration result is
  represented here.

## Skipped lanes

Cache H1 and forward H1/H2/H3 remain skipped because their OxiRoute daemon paths are fail-closed.
Reverse H2 requires the separate TLS/ALPN load matrix, and reverse H3 is not implemented. A skipped
lane is not a zero-throughput result.
