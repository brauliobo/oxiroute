# Invalidated local-v1 reverse HTTP/1.0 diagnostic - 2026-07-23

## Result

ApacheBench emitted `HTTP/1.0` request lines despite the original report describing this as an
HTTP/1.1 lane. This report is retained to make that measurement error explicit, but its ratios are
invalid as an HTTP/1.1 baseline and must not be used to assess subsequent optimizations. Three
measured 30-second repetitions completed for each implementation with zero failed or non-2xx/3xx
requests.

| Direct nginx origin | 487,281 | 488,706 | 491,126 | 488,706 | 0.32% |
| nginx 1.30.4 | 193,177 | 169,816 | 194,336 | 193,177 | 6.08% |
| HAProxy 3.4.2 | 125,854 | 132,061 | 143,549 | 132,061 | 5.48% |

For this invalidated HTTP/1.0 diagnostic only, OxiRoute delivered 43.19% of nginx throughput and
63.18% of HAProxy throughput.
nginx delivered 2.32x OxiRoute throughput; HAProxy delivered 1.58x. The direct origin delivered
2.53x the fastest proxy result, satisfying the origin-headroom check for this scenario.

OxiRoute had the highest dispersion. Its 10.08% population coefficient of variation makes this a
useful baseline and optimization signal, but more repetitions on an isolated performance host are
required before drawing a strong ranking conclusion.

## Method

- Scenario: plaintext HTTP/1.0 keep-alive input over loopback with a fixed 1,024-byte response.
- Load: ApacheBench 2.3, 128 keep-alive connections, 10-second warm-up, 30-second measurement.
- Repetitions: three per implementation. Proxy order was interleaved across repetitions rather than
  running one implementation's complete set consecutively.
- CPU affinity: proxy CPU 2, nginx origin CPU 3, load generator CPU 4.
- Concurrency: one OxiRoute/Pingora service thread, one nginx worker, one HAProxy thread.
- Validation: status and exact response size were checked before every warm-up; every measured run
  reported zero failed and zero non-2xx/3xx requests.
- Product source: `827f726162fe36ef2bdebef78ff18bd47ec5c58a`.
- OxiRoute binary SHA-256:
  `5f8b7f378ec9ccd71d4cb987a5f4261315a5957e5ea5c1be181211ff10d2604b`.
- Host: AMD Ryzen 7 9700X, Linux `7.1.3-2-cachyos`, 16 logical CPUs.

The direct repository harness is authoritative for these samples. The local Phoronix profile was
validated but was not the executor for this report.

## Limitations

- The host used the `powersave` governor with boost and SMT enabled. CPUs were pinned but not
  isolated from kernel or workstation activity.
- ApacheBench emitted HTTP/1.0 and normalized connection behavior differently across products. It
  is also a closed-loop client subject to coordinated omission. This report
  contains throughput and failure counts, not trustworthy tail-latency distributions.
- Access logging was disabled and all products used one worker/thread, matching OxiRoute's current
  fixed service-thread behavior.
- No TLS, HTTP/2, HTTP/3, remote-network, multi-core, memory, CPU-counter, or long-duration result is
  represented here.
- An earlier unpinned three-run diagnostic varied by 2.5x to 6.1x and was rejected rather than
  included in the aggregates.

## Skipped lanes

Cache H1 and forward H1/H2/H3 remain skipped because their OxiRoute daemon paths are fail-closed.
Reverse H2 requires the separate TLS/ALPN load matrix, and reverse H3 is not implemented. A skipped
lane is not a zero-throughput result.
